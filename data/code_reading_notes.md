# code_reading.json: журнал проверки (09.11.2026)

Файл данных: `data/code_reading.json`, 10 записей. Все клоны сделаны с `--depth 1` в `/tmp/ctrain.82P3iD` и удалены в конце.
Скрипт сборки и проверки лежал вне проекта (папка scratchpad сессии), запускался как `python3 -I`.

## Что проверено автоматически для каждой записи
- HEAD клона равен SHA в permalink.
- Путь файла существует; blob SHA файла на GitHub (`gh api .../contents/<path>?ref=<sha>`) совпадает с локальным `git rev-parse <sha>:<path>`.
- Страница permalink отвечает HTTP 200.
- Диапазон строк не длиннее 80; первая строка содержит сигнатуру функции, последняя закрывает её.
- Номера строк в ответах не выходят за конец файла.
- Crossref (`api.crossref.org/works/<doi>`): заголовок, журнал и год совпали с записанными. Все 10 DOI зарегистрированы (`doi.org/api/handles`, responseCode 1).
- Язык репозитория сверен с `gh api repos/...` (поле `language`).
- Что статья про этот инструмент: DOI найден в README, CITATIONS.md или inst/CITATION самого репозитория (minimap2, miniprot, hifiasm, Biopython, DESeq2, Scanpy, nf-core/rnaseq, bcftools, Merqury). У Mash в README ссылки нет, она есть в `doc/sphinx/index.rst`.
- Ответы на вопросы получены чтением кода. Дополнительно запускалось: SimpleFastaParser Biopython на тестовых строках (вырезан из файла и выполнен через exec); арифметика формул QV и p-value Mash (python3 -I). Сами программы (minimap2, meryl, Mash и т.д.) не собирались и не запускались.

## Что не удалось или отличается от ожиданий
- `curl -I https://doi.org/10.1093/...` для DOI издательства OUP (bty191, btad014, btp163, giab008) отдаёт 403 (защита от ботов). Регистрацию DOI подтвердил через `doi.org/api/handles` (responseCode 1, целевой URL на academic.oup.com). Остальные DOI отдали 200.
- Лицензия: у minimap2, Biopython, bcftools, Merqury и Mash GitHub API возвращает `NOASSERTION` / Other, у DESeq2 `null`. В поле `license` записан текст из файла LICENSE (или DESCRIPTION у DESeq2) с пометкой про API.
- DESeq2: репозиторий `mikelove/DESeq2` перенаправляет на `thelovelab/DESeq2` (проверено `gh api`), ветка `devel`, версия в DESCRIPTION 1.53.7. Лицензия LGPL (>= 3).
- nf-core/rnaseq: DOI относится к статье про фреймворк nf-core, а не к одному пайплайну (README репозитория сам просит цитировать её). Отдельной статьи про rnaseq быстрый поиск по Crossref не нашёл (поиск не исчерпывающий). Записано в `unverified` записи.
- Merqury: в репозитории Shell-скрипты без функций, поэтому «функцией» взят основной цикл `eval/qv.sh` (строки 50-83). `meryl` и `bedtools` не установлены, поэтому смысл вывода `meryl statistics` и `meryl-lookup` не проверялся запуском. Формула QV сверена с примером на вики Merqury: строка `682359 / 123511626 -> QV 35.1183, ошибка 0.000307729` воспроизводится при k = 18, но k на странице не указан (подобран по числам).
- Mash: смысл `gsl_cdf_binomial_Q` не сверен с руководством GSL (сайт gnu.org не ответил за 120 с, зависший запрос остановлен). Совпадение с хвостом биномиального распределения подтверждено документацией самого Mash (`doc/sphinx/distances.rst`).

## Что заменено и почему
- hifiasm: первой целью была `ha_analyze_count` (поиск пиков k-мер, определяет покрытие гомозиготных k-мер), но её 84 строки (hist.cpp:74-157) превышают лимит 80. Взята `print_hist_lines` (hist.cpp:15-44) с той же логикой начала. Проверка `rg print_hist_lines` по всему репозиторию: определение и объявление в htab.h, вызовов нет, то есть функция не используется в этом коммите. Это прямо сказано в `what`, а один вопрос сравнивает её с рабочей `ha_analyze_count`. Другой кандидат, `asg_end` (gfa_ut.cpp:527-552), отброшен: файл на 18 тысяч строк, неудобен как точка входа.
- Mash: `compareSketches` (CommandDistance.cpp:336-425, формула расстояния в строке 401) занимает 90 строк, поэтому взята `pValue` (427-448). Формула расстояния упомянута в `what` со ссылкой на строку 401.
- bcftools: `subset_vcf` (vcfview.c:307-469, фильтры) занимает 163 строки, поэтому взята `bcf_p1_call_gt` (prob1.c:181-208, байесовский вызов генотипа). Раздел «фильтрация вариантов» в записи не раскрыт.
- scanpy: вместо большой `normalize_total` (около 175 строк вместе с docstring) взят вспомогательный `_normalize_total_helper` (110-165).
- Выбор четвёртой темы: вместо samtools/htslib взят Biopython (`SimpleFastaParser`), потому что код короткий и на Python. Статья samtools/bcftools (giab008) использована один раз, для bcftools.
- BUSCO отброшен: основной репозиторий на GitLab, не GitHub. Вместо него Merqury (Genome Biology 2020).

## Заметки по ходу чтения (не вошли в JSON)
- scanpy `_normalization.py:148`: в ветке CSR + `exclude_highly_expressed` стоит `gene_subset = ~np.where(counts_per_cols)[0]`. Оператор `~` применён к массиву индексов, а не к булевой маске, как в плотной ветке (строка 154). Похоже на ошибку, но поведение не запускалось и апстрим не сообщался.
- minimap2 `mm_sketch`: пустая запись `info` равна `UINT64_MAX`, и сравнение `info.x <= min.x` истинно, когда `min` тоже пустой. Защищают от записи проверки `min.x != UINT64_MAX`.
